# instagram-auto-post

太陽と月モチーフの天然石ピアス作品を、Googleスプレッドシートで管理した予定に沿って
Instagramフィード・ストーリーズに自動投稿する仕組みです。

## 仕組み

### フィード投稿
1. Googleスプレッドシート「投稿管理」タブに投稿予定を1行ずつ登録する
   (投稿日時・画像ファイル名・商品名・使用石・BASE商品URL・投稿済みフラグ)
2. GitHub Actionsが1日4回(10:00 / 13:00 / 18:00 / 20:00 JST)自動実行される
3. 投稿日時を過ぎていて未投稿の行を見つける
4. Claude APIでキャプションを生成する(石の効果を断定しない、やさしい文体)
5. `TEST_MODE=true` のときは投稿せず、生成キャプションをスプレッドシートに書き込むだけ
6. `TEST_MODE=false` のときはInstagram Graph APIで実際に投稿し、結果をスプレッドシートに記録する
7. 失敗した行は「エラー」フラグと理由をスプレッドシートに記録し、他の行の処理は続ける

### ストーリーズ投稿
1. Googleスプレッドシート「ストーリー管理」タブに投稿予定を1行ずつ登録する
   (投稿日時・動画ファイル名・投稿済みフラグ)
2. 同じGitHub Actionsの実行の中で、フィード投稿の処理のあとにチェックされる
3. 投稿日時を過ぎていて未投稿の行のうち、**同じ日にフィード投稿の予定がある行はスキップ**する
   (「スキップ」フラグと理由が記録される)
4. それ以外はInstagram Graph APIで動画をストーリーズとして投稿する
5. フィード投稿と同様、テストモード・エラー記録の仕組みも共通

## セットアップ手順

初めての方は [docs/setup.md](docs/setup.md) を上から順番に進めてください。
Googleスプレッドシート作成 → Google連携 → Instagram連携 → Claude APIキー → GitHub Secrets登録
→ テストモードでの動作確認 → 本番切り替え、の順で説明しています。

## ローカルでのテスト実行

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # .env を編集して値を埋める
cd scripts
set -a; source ../.env; set +a
python main.py
```

`TEST_MODE=true` のままなら、実際には投稿されず、生成されたキャプションが
ターミナルとスプレッドシートの「結果メモ」列に出力されます。

## スプレッドシートの列構成

### 「投稿管理」タブ(フィード投稿)

1行目(ヘッダー)に以下の列名を **この通りに** 入れてください。

| 列名 | 内容 |
|---|---|
| 投稿日 | 投稿したい日付。カレンダーから選択可(表示形式を「日付」にした場合) |
| 投稿時刻 | 投稿したい時刻。例: `10:00` |
| 投稿日時 | 旧形式(互換用)。「投稿日」「投稿時刻」が空欄の行だけこちらが使われる。新規の行では空欄でよい |
| 画像ファイル名 | `posts/` フォルダに置いたファイル名。例: `sun_moon_01.jpg` |
| 商品名 | 例: `太陽と月のピアス(サンストーン)` |
| 使用石 | 例: `サンストーン` |
| 内包物 | 石のきらめきの由来となる鉱物名。例: `レピドクロサイト`(わからない場合は空欄でOK。空欄の場合、キャプションは鉱物名を創作せず一般的な表現になります) |
| BASE商品URL | 商品ページのURL(参考情報。キャプション本文には貼りません) |
| 撮影場所(任意) | 写真を撮った場所を一言で。例: `近所の川辺`。書くと、投稿文の1文目が「フォロワーさんの耳と〇〇へ行ってきました」の形で、その場所の名前を使って作られます。空欄なら、場所の名前は書かず、写真に写っているものだけを描写します |
| 商品タグID | Facebookコマースマネージャーの商品カタログに登録された商品ID(わかる場合のみ。空欄なら商品タグなしで投稿されます) |
| 投稿済みフラグ | 空欄=未処理 / `投稿済み` / `エラー`(スクリプトが自動更新) |
| 投稿日時(実績) | 実際に処理した日時(スクリプトが自動更新) |
| 結果メモ | エラー内容、またはテストモード時の生成キャプション(スクリプトが自動更新) |

### 「ストーリー管理」タブ(ストーリーズ投稿)

こちらも1行目(ヘッダー)に以下の列名を **この通りに** 入れてください。

| 列名 | 内容 |
|---|---|
| 投稿日 | 投稿したい日付。カレンダーから選択可(表示形式を「日付」にした場合) |
| 投稿時刻 | 投稿したい時刻。例: `12:00` |
| 投稿日時 | 旧形式(互換用)。「投稿日」「投稿時刻」が空欄の行だけこちらが使われる。新規の行では空欄でよい |
| 動画ファイル名 | `stories/` フォルダに置いたファイル名。例: `story1.mp4` |
| 投稿済みフラグ | 空欄=未処理 / `投稿済み` / `エラー` / `スキップ`(同じ日にフィード投稿があった場合。スクリプトが自動更新) |
| 投稿日時(実績) | 実際に処理した日時(スクリプトが自動更新) |
| 結果メモ | エラー内容・スキップ理由・テストモード確認(スクリプトが自動更新) |

#### YouTubeショート用の文章(任意)

次の3列をストーリー管理タブに足すと、YouTubeショートに付けるタイトル・説明文・ハッシュタグをClaudeが自動で作ります。
動画のアップロードと公開予約は、YouTube Studioで手動で行います(YouTube APIの審査が必要になるため自動化していません)。

| 列名 | 内容 |
|---|---|
| 商品名 | 「投稿管理」タブにある商品名と同じ文字列を入力(使用石・内包物・写真はそちらから自動で引く) |
| YouTubeタイトル | 自動で入力される。コピーしてYouTube Studioに貼る |
| YouTube説明文 | 自動で入力される(ハッシュタグを含む)。コピーしてYouTube Studioに貼る |

- 商品名が「投稿管理」タブに見つからないときは、タイトル欄に `[要確認]` と表示され、商品名を直すと次の実行で自動的にやり直される
- 生成に失敗したときは、タイトル欄に `[エラー]` と理由が表示される。タイトル欄を空にすると再生成される
- Instagramの投稿とは独立していて、失敗してもInstagramの投稿には影響しない

#### X(旧Twitter)用の投稿文(任意。Xへの投稿は未実装)

「投稿管理」タブに `X投稿文` という列を足すと、まだInstagramに投稿していない行(商品名と画像ファイル名がある行)について、
写真に添える短い紹介文+BASE商品URL+ハッシュタグ(最大3個。石の名前は本文には書かず、ハッシュタグにだけ使う)をClaudeが自動で作って、その列に書き込みます。
Xへの実際の投稿は、まだ行いません(Xの開発者アカウントとAPIキーを用意したあとに実装する予定)。

- 生成に失敗したときは、`[エラー]` と理由が入る。セルを空にすると、次の実行で作り直される
- Xの文字数の数え方(日本語は1文字を2、URLは23として、合計280まで)で上限を超えたときも、エラーになる
