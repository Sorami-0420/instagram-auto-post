# 注意点とノウハウ集(Claudeが会話の最初に読む資料 ②)

これまでの作業で起きた失敗・つまずき・うまくいった手順をまとめたものです。同じ間違いを繰り返さないために、会話を始める前に読むこと。
**公開リポジトリに置くため、パスワード・APIキー・IDは含めていません**(IDは `docs/private/ids.md`)。

## A. そらみさんとの進め方

- **プログラミングは初心者。** ターミナルやFinder、画面の用語も、1つずつ説明する。コマンドは、コピーして貼るだけで動く形で出す(説明文との混同を避けるため、1コマンドずつコードブロックに入れる)
- **画面の言葉を取り違えやすい。** 例: Googleスプレッドシートのメニューは「数値」ではなく「**数字**」。「ドロップダウン」「ターミナル(アプリ内のパネルとMacのターミナルは別物)」なども、画面のスクリーンショットで確認してから案内する
- **スクリーンショットで状況を共有してくれる。** 推測せず、画面を見せてもらってから判断する。長時間の切り分けのときは、確認してほしい場所のURLと手順を番号で示す
- **コミット・pushは、毎回「コミット・pushしてよいですか」と聞いて、「はい」をもらってから行う。** GitHubは公開リポジトリなので、pushする前に、秘密情報が含まれていないか確認する
- **秘密情報(APIキー、トークン、パスワード)は、チャットに貼らせない。** 一度、コマンドの実行結果にキーが表示されて漏れそうになったことがある。確認用のコマンドは、値を表示しない形(長さや行数だけ数える等)にする。貼られてしまったら、すぐ無効化して作り直すよう案内する
- **安定性を重視する人。** 自動化の選択肢を出すときは、「壊れやすさ(非公式のしくみ、外部サービスの仕様変更、審査)」を必ず並べて書き、基本は確実な方を勧める。「手間は減るが壊れやすい」案を黙って選ばない
- **細かい調整を、短い往復で何度も依頼してくる。** 依頼されたら説明を長くせず、直して、確認の手順を添える。範囲を勝手に広げない
- **「撮影場所」列の言葉は、そらみさんが意図して書いたもの。** 場所を特定されたくないため、実際とは違う言葉(例:「公園」)を書くことがある。間違いだと決めつけず、そのまま使う。説明的な言葉(例:「秋を感じられる場所」)のときは、「〇〇へ」ではなく「〇〇でひと休みしてきました」のように助詞を合わせる(プロンプトに反映済み)
- **Xの2文目のデザイン説明は、写真で確実に分かる形・色・光だけ。** 羽根・三日月などの具体的な形を、写真や商品名で確実でないのに書かない(過去に太陽型のピアスを「羽根と三日月」と書いた)。素材の名前(銀・金など)も書かない(素材はステンレスまたはロジウムで、見た目から断定できないため)。小さな石の粒を「実」などに見立てて書かない。石の色名(赤・オレンジなど)も書かない(複数の色が混ざる石を、プロンプトの例のまま全部「赤い石」と書いたことがあるため。「あたたかな色合いの石」のように色名を避ける)
- **できないこと・確認できていないことは、正直に言う。** 例: 「公開だけ手動でできる」と確認不足のまま言って、訂正した。調べて分かった事実と、推測は分けて書く

## B. 絶対に守ること(安全)

- 公開リポジトリに、`.env`、`service-account.json`、トークン、キーを入れない(`.gitignore` 済み)。`posts/` と `stories/` の画像・動画は、Instagramが取得するため公開される
- 実際にInstagramへ投稿する操作(`test_mode: false` の実行、`TEST_MODE` の変更)は、必ず本人の確認を取ってから。投稿は取り消しできない
- 原因が分かるまで、失敗した処理を手動で再実行しない(二重投稿を避けるため)。まず「何も投稿されていないか」を確認する

## C. 技術的な落とし穴(実際に起きたもの)

- **GitHubの変数 `TEST_MODE`**: 作られていないと、自動実行は常にテストモード(`true`)で動き、投稿されない。「Run workflow」の `test_mode` 入力欄は、毎回デフォルトが `true`(安全のため)で、変数とは別物。手動で本番投稿するときは、入力欄を `false` にする。設定は Settings → Secrets and variables → Actions → **Variables** タブ(Secretsではない)
- **自動実行は1日5回(07:07 / 07:37 / 12:07 / 20:07 / 20:37 JST)。** Macの電源は不要(GitHubのサーバー上で動く)。投稿予定時刻の「ちょうど」には投稿されず、次の実行で処理される。**毎時0分は、GitHubが混雑して遅れる・実行が捨てられることがある**(公式の説明)。実際に、2026-10-04の20:00の予定が、毎時0分の実行の遅れで、翌0:56の投稿になった。そのため0分を避けてずらし、夜と朝は2回ずつにした。投稿したい時刻より前の実行では投稿されないので、新しく時刻を増やすときは、その時刻の少し後に実行を足す
- **Instagramのアクセストークンには期限がある**(`docs/setup.md` では約60日の想定)。最後に作り直したのは2026-09-30。切れるとInstagramへの投稿がエラーになるので、**2026年11月下旬までに更新を案内する**(手順は `docs/setup.md` のSTEP 4と6。新しいトークンは、本人が自分のブラウザ内だけで扱い、チャットには貼らせない)
- **Googleスプレッドシートが一時的に503を返す**ことがある。再試行する仕組み(`scripts/sheets_retry.py`)を入れてある。それでも失敗して何も処理されなかったときは、次の自動チェック(最大で約2〜14時間後)か、手動実行で処理される
- **macOSのファイル名はNFD(分解形)、スプレッドシートの文字はNFC(合成形)。** 見た目が同じでも一致しない。商品名との照合は、必ずNFCに揃えて比較する(`unicodedata.normalize("NFC", ...)`)
- **テストモードは「投稿済みフラグ」を変えない。** エラー(`エラー`)になった行は、人がフラグを空欄に戻さないと再処理されない。**投稿日が未来の行は、テストモードでも処理されない**
- **画像ファイル名が空欄だと、投稿日になってもその行は投稿されず「画像読み込みエラー」になる。** 写真は `add_photo.command` で追加する(自動で商品名の行に入る)
- **AIは文字数の指示を守れないことがある。** プロンプトに「25文字以内」と書いても守られなかった。守らせたいルールは、**出力を機械的に検査して、違反があれば、文言を変えずに直させる**(`rewrap_if_needed`。文言が変わったら元を使う)形にすると確実
- **Claude APIでWeb検索ツールを使うとき、`max_tokens` は大きくする(8000)。** 小さいと `stop_reason=max_tokens` になり、本文が空で返ってくる
- スマホでInstagramを見ると、**1行目の先頭にアカウント名が付く。** 1行目は15文字以内、それ以外は28文字以内にする
- **Safariの翻訳機能が、日本語の投稿の表示を書き換えることがある。** Xに手動投稿した直後、「、」が増えたり文がおかしくなったりして見えたが、アドレスバーの「文A」マークから翻訳をオフにすると、元の文章(シートと同じ)に戻った。文章がおかしく見えたら、投稿を消す前に、まず翻訳をオフにして確かめる
- ローカルのPythonは3.9。`FutureWarning` / `NotOpenSSLWarning` は無視してよい。ローカルには `anthropic` が入っていないので、動作確認は偽物(スタブ)に差し替えて行う
- `grep` で `(^^)` のような記号を探すときは `-F` を付ける(付けないと一致しない)

## D. 作ったがうまくいかなかったもの(同じ道を繰り返さない)

- **Instagramの商品タグ付けの自動化は未解決。** コードは入っているが動かない。原因は、Instagramショッピングに実際に接続されているカタログが、アプリ側からアクセスできる「Sorami カタログ」とは別の、自動生成された「Products for Sorami」だと見られること。Metaのアカウント構成の問題で、長時間調べても解決しなかった。商品タグは、Instagramアプリから手動で付けている。**本人が再挑戦を望まない限り、蒸し返さない**
- **YouTubeのAPIで自動アップロードはしない。** 2020年7月28日以降に作ったAPIプロジェクトは、Googleの審査に通るまで、アップロードした動画が必ず「非公開」に固定される。YouTube Studioで公開に直すこともできない。審査フォームは企業向けの内容(プライバシーポリシーURLなどが必須)で、個人用スクリプトは通る見込みが低いと判断し、申請は見送った。代わりに、**タイトル・説明文・ハッシュタグだけを自動生成**し、アップロードと公開予約は手動で行う運用にした
- 動画編集の自動化(CapCutの下書き生成、ffmpeg、AI動画生成など)は見送り。理由は、非公式の形式に依存して壊れやすいため。本人から「AIの進化で動画編集を自動化できるようになったら教えてほしい」と頼まれている。聞かれたら、その時点の最新状況を調べて答える(Claudeから勝手に通知はできない)

## E. よく使う手順(ノウハウ)

### 写真を追加する(フィード投稿)
1. 写真のファイル名を商品名と同じにして `~/Pictures/フィード投稿用/` に置く
2. スプレッドシート「投稿管理」に、商品名・使用石・内包物・投稿日・投稿時刻を入力(画像ファイル名は空欄)
3. `scripts/add_photo.command` をダブルクリック → 写真を選び、半角英数字の名前(例: `item10.jpg`)を入力 → 公開と、シートへの自動入力まで行われる

### ストーリー動画を追加する
1. 「ストーリー管理」に、投稿日・投稿時刻・商品名を入力(動画ファイル名は空欄)
2. `scripts/add_story.command` をダブルクリック → 動画を選び、半角英数字の名前を入力 → 「投稿日は入力済みで動画ファイル名が空欄」の一番上の行に自動で入る
3. 商品名を入れると、数時間以内に「YouTubeタイトル」「YouTube説明文」が自動で入る。作り直したいときは、タイトルのセルを空にして「Run workflow」を実行

### 投稿されたか確認する
- GitHub Actionsの実行履歴: `curl -s "https://api.github.com/repos/Sorami-0420/instagram-auto-post/actions/runs?per_page=5"`(ログの中身は認証が必要で取れないので、失敗時は本人に画面を見せてもらう)
- スプレッドシートの内容: ローカルの `service-account.json` と `.env` を使い、`scripts/story_sheets_client.py` / `scripts/sheets_client.py` で読み取る(読み取りだけなら安全)
- 公開された写真が取得できるか: `curl -s -o /dev/null -w "%{http_code}" https://raw.githubusercontent.com/Sorami-0420/instagram-auto-post/main/posts/<ファイル名>`
- 「投稿された」と言う前に、シートのフラグと、実行結果の両方を見る。確認できていないことは、確認できていないと言う

### 失敗したとき
1. 実行履歴で失敗した実行の「post」→「Run posting script」のログを、本人にスクリーンショットで見せてもらう
2. 何も処理されずに止まったのか、途中まで投稿されたのかを判断する(Instagramのプロフィールも見てもらう)
3. 原因を直してから、必要なら `test_mode: false` で手動実行(本人に確認を取る)
