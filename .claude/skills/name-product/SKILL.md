# 商品名を考える手順

写真(と、使った石・モチーフの説明)を受け取って、商品名の候補を出し、決まるまで磨く。

## 始める前に確認すること
1. 写真を見て、モチーフ・色・形・背景を読み取る(HEICは `sips -s format jpeg` でjpegに変えてから読む)
2. 石の名前は、そらみさんが言った名前が正本(写真から決めつけない)。聞き間違い・打ち間違いに見えたら、先に確認する(例: 「天眼ゲート」→「天眼アゲート」)
3. すでに使った名前・言葉を避ける。スプレッドシートの商品名列とBASEの商品一覧が正本。これまでに避けた例: 「陽だまり」「おひさま」「小さな太陽」「陽をまとう」「道しるべ」(使用済みは、決まるたびに増える)
4. 「太陽」「月」は、写真・モチーフから読み取れるときだけ使う(ブランドのテーマだが、全商品のモチーフではない)

## 候補の出し方
- 3つの系統に分けて、7〜9案。例: 情景・物語 / 色・石の名前 / かわいい・短い言葉
- 今までの名前の雰囲気は、情景や物語を想像させる、少し詩的な言葉(例: 「落ち葉に眠る月」「葉音に応ふる月影」「秋陽に輝くガーネット」「記憶に揺れる茜月」)。かわいい路線の名前もある(「桃色おひさまのティータイム」)
- 対になる商品があるときは、名前も対にできる(例: 「コウモリの隠れ家」と「紅い月の見張り番」。形は「〇〇の△△」でそろえ、役割を対比させる)
- 似た商品があるときは、名前の頭をそろえて、違いが分かる言葉を足す(例: 「桃色おひさま」+「ふわふわ」「とおともだち」)
- おすすめを2つ選び、理由を一言ずつ書く。選ぶ基準は、石やモチーフが想像できること・短くて覚えやすいこと
- 最後に、確認の質問を1つだけ(時間帯のイメージ・コウモリなどのモチーフの位置・場所の扱いなど)。質問を何個も並べない

## 落とし穴
- 見えないものを名前に入れると、「どこにあるの?」となる。入れるなら、商品文で補う(例: コウモリの羽は、写真では虹色の飾りにしか見えない)
- 染めた石を、本来の名前で呼ばない(例: 赤く染めたサンゴを「紅珊瑚」「血赤」としない。実態と違う説明になる)
- 素材名(銀・金・真鍮など)は、見た目から断定しない。名前には入れない
- 石の効果・意味を断定する名前にしない
- 背景・場所を名前に入れるときは、先に確認する(撮影場所は、特定されたくない場合がある。実際と違う言葉のこともあるが、そのまま使う)
- 「時間帯」(朝・夕方)や「季節」(ハロウィン)は、写真・撮影時刻から読み取れる。そらみさんに聞くと、名前が磨ける(例: 夕方の写真 → 「暮れなずむ」)
- コウモリなど、意味のあるモチーフの言い伝えは、Web検索で確認してから書く。中国では「福」と同じ発音から縁起がよい、は確認済み。「再生」「直感」などは根拠が見つからなかったので、使わない

## 決まったあと
1. 写真のファイル名は、商品名と同じにする(例: `コウモリの隠れ家.jpeg`)。置き場所は `~/Pictures/フィード投稿用/`
2. スプレッドシートの「使用石」列は、そらみさんの表記のまま(染めは「(染め)」「(染色)」と分かる形)
3. 次の作業を、選択肢で出す(商品文の下書き / スプレッドシートへの入力 / 写真の追加)
4. 商品文は、スキル `write-base-description` で書く
